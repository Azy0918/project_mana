# 過去のループデッキ調査(闇系中心)

Web検索で確認した実在ループの構造分解と、本シミュレーターのループ原語マッピング。
ループ探索器(不動点検出)の設計基礎資料。

## 実在した闇系ループの系譜

### 1. サガループ(水闇, 2023年・本家)
- **核**: 《絶望神サガ》×2枚のみで自己完結する相互蘇生ループ
- **サイクル**: サガA着地 →(出た時)墓地のサガBを蘇生(コスト5以下)→ 自分のクリーチャー1体破壊(A自壊)→ サガB着地 →(出た時)墓地のAを蘇生 → …
- **収支**: 「出た時」誘発を無限に発生させ、付随ドロー・墓地肥やしで山札を掘り切り任意のフィニッシャーへ。最速3ターン
- **結末**: 殿堂入り。歴代最強級ループとの評価

### 2. オカルトアンダケイン(闇単中心, 2020年・本家)
- **核**: 《不敵怪人アンダケイン》(フシギバース=場のクリーチャーをコストにして墓地から召喚)+《フォーエバー・オカルト》
- **サイクル**: 場のクリーチャーをコスト化→墓地から再展開→《フォール・クロウラー》(相手マナ送り)《ラビリピト》(全ハンデス)を使い回し
- **収支**: 相手のマナと手札を毎周削り、最終的にライブラリアウト
- **結末**: 2021年7月、アンダケイン等の殿堂入りで終焉

### 3. MRCロマノフループ(闇/赤黒, DMR期・本家+デュエプレ実装)
- **核**: 《M・R・C・ロマノフ》(攻撃時、墓地の呪文を3枚まで唱え、唱えた呪文を山札の下へ)+蘇生呪文セット(《インフェルノ・サイン》《法と契約の秤》等)
- **サイクル**: 墓地呪文3枚発射→呪文は山札下へ戻る(=弾の再装填)→蘇生で2体目のMRC/ロマノフⅡ世→再攻撃→無限蘇生で《ガジラビュート》(シールド焼却)・《学校男》(自壊除去)を無限回着地
- **収支**: シールド全焼却+盤面全壊からのワンショット

### 4. ヴォルグ・サンダーLO/ザビミラ型(闇+水自然, 2011年頃・本家+デュエプレ)
- **核**: 《復活の祈祷師ザビ・ミラ》(自分クリーチャーをサイキックに変換)+《ヴォルグ・サンダー》(出た時、相手山札からクリーチャー2枚が落ちるまで墓地送り)
- **サイクル**: 厳密な無限ループではなく「大量変換による一斉山札破壊」
- **結末**: ヴォルグは本家でプレミアム殿堂。**デュエプレでも環境入りし運営調整が入った=デュエプレ史の代表的な闇系疑似ループ**

### 5. 無限死神/ヒドラ系(闇, 最古典・本家)
- **核**: 《凶星王ダーク・ヒドラ》(種族クリーチャーの墓地回収)+《死神術士デスマーチ》等の軽量墓地進化・自壊
- **サイクル**: 自壊→ヒドラで回収→再展開、の半永久リソースエンジン
- **位置づけ**: 「歴代名作デッキ」に数えられるループの祖型

### デュエプレ特有の注意
デジタル実装のデュエプレでは無限ループはクライアント側で回数制限・カード調整(ナーフ)
の対象になる。研究上は「無限」ではなく**「1ターン内の大量反復(有限ループ)」**として
モデル化するのが正しい。

## ループ原語マッピング(本シミュレーターとの対応)

| ループ型 | 必要な原語 | 現状 |
|---|---|---|
| **サガ型(相互蘇生)** | summon_from_grave + 自壊(destroy scope self) + 出た時の再帰発火 | **すべて実装済み**。表現・検出が現エンジンの射程内 |
| ヒドラ型(回収エンジン) | grave_to_hand + 自壊 + 再召喚 | ほぼ実装済み(種族条件は近似) |
| MRC型(呪文再装填) | cast_from_grave + 唱えた呪文の山札下戻し | 未実装(cast_from_grave op が必要) |
| アンダケイン型(フシギバース) | 場のクリーチャーをコスト化する代替召喚 + 置換効果 | 未実装(コスト変換・置換効果) |
| ザビミラ型(超次元変換) | 超次元ゾーン | 未実装 |

**重要な含意**: 史上最強級とされるサガ型の構造(A出た時→B蘇生→自壊、Bも同様)は、
summon_from_grave・scope self破壊・再帰実行(深さ5)を実装済みの現エンジンで
**既に表現可能**。ループ探索器の第一弾は「相互蘇生対の静的検出
(AのEffectScriptがBを蘇生でき、BがAを蘇生できる組)+収支検証」から始められる。

## ループ探索器の設計方針(次フェーズ)

1. **静的スクリーニング**: 承認済みEffectScriptから「蘇生/回収/踏み倒しを持つカード対」を列挙し、
   相互到達(A→B→A)とコスト収支(蘇生上限≧相手のコスト)を機械判定
2. **動的検証**: 候補対を一人回しに投入し、1ターン内の反復回数を計測
   (回数が深さ上限に張り付く=ループ成立のシグナル)
3. **デュエプレ準拠**: 反復上限付きの「有限大量ループ」として評価(無限判定はしない)

## ループ探索器・第一弾の実行結果(2026-06)

`python -m src.battle.research loop-find` を実装・実行した。

- **検出能力の証明**: サガ構造(自壊→自己蘇生)の合成カードを反復上限到達として
  正しく検出し、自壊なしの単純蘇生は有限(墓地コピー数で停止)と正しく区別する
  (tests/test_loop_finder.py)。
- **実プールでの結果**: 静的候補556件、上位の「ループ署名」(阿修羅サソリムカデ、
  偽りの名 ドレッド・ブラッド、ジグス★ガルビ等)を原文照合した結果、
  **すべて近似由来の偽陽性**だった:
  - 阿修羅サソリムカデ: 原文は「自身以外・マフィ・ギャング限定」の蘇生+
    「ターン終了時」破壊 → 変換で3制約とも欠落
  - ジグス★ガルビ: 「無月の門を使った時」の条件付き誘発 → 無条件on_playに誤変換
  - ドレッド・ブラッド: 「ターン開始時、墓地にあれば」 → on_playに誤変換
- **結論**: 「ループは近似に殺される/近似はループを捏造する」の両面が実証された。
  探索器は完成しており、ボトルネックは世界モデルの精度。偽陽性リストが
  そのまま精密化の作業リスト:
  1. 蘇生の「自身以外」フラグ(exclude_self)
  2. 種族フィルタ(race)
  3. 「ターン終了時」タイミング(現状は即時破壊に近似)
  4. 条件付き誘発(無月の門・ターン開始時等)を変換不可として下書きに残す
     (誤って無条件承認しない)精度ゲートの強化


## 第二弾: 忠実度ゲート導入とexact限定再走の結果(2026-06)

偽陽性4点セットへの対策を実装した:
- `fidelity` 列(exact/approx)を card_effects に追加。**自動下書きは常にapprox**、
  exactはキュレーションで明示した場合のみ。`load_approved_effects_map(exact_only=True)`
  でループ探索は精密集合だけを見る
- 精密パラメータ: `summon_from_grave` に exclude_self / exclude_evolution / race、
  `destroy_creature` に timing="end_of_turn"(遅延破壊キュー)を追加
- ループ関連カード11種を原文照合してexactキュレーション
  (`data/effect_scripts/curated_loops_exact.json`)。条件付き能力(無月の門・
  ターン開始時・種族条件)は**表現できないものを省略=過小評価側に倒す(exact-safe)**

**exact限定 loop-find の結果: 静的候補0件。**

結論: 精密にモデル化した範囲において、現デュエプレプールに
サガ型(無条件の相互/自己蘇生)ループは存在しない。クリーチャーの自己蘇生は
すべて「無月の門」等の条件ゲート付きであり、これは実ゲームの制約とも一致する。
ループへの残された道は: (1) 条件付き誘発のモデル化(無月の門=魔導具メカニズム)、
(2) MRC型(cast_from_grave)の実装、(3) exactキュレーションの対象拡大。
偽陽性ゼロの探索基盤は完成しており、今後exact集合を広げるたびに
この問いへの答えが自動更新される。

既知のデータ課題: cards.race列が空(種族データ欠落)のため、
種族限定蘇生(マフィ・ギャング等)はexact表現不可。取り込み側の修正が必要。


## 第三弾: MRC型エンジンの実装と歴史的ループの初再現(2026-06)

`cast_from_grave` op(墓地の呪文を無償詠唱→山札の一番下へ)と、蘇生への
SA付与(`speed_attacker`)・文明フィルタ・「相手が選ぶ」破壊(`chooser`)を実装。
プールに実在するMRC型の部品(邪眼大帝 ラスト・ロマノフ/暗黒GUY・ゼロ・ロマノフ/
煉獄と魔弾の印/冥府の覇者ガジラビュート/学校男/法と契約の秤)を原文どおり
exactキュレーションした。

**再現実験(史実盤面: ゼロ・ロマノフ1体+墓地に印3・ガジラビュート2・ゼロ1)**:

```
ゼロ#1攻撃 → 印を墓地詠唱 → ゼロ#2をSA付き蘇生 → #1がシールド2枚ブレイク
ゼロ#2攻撃 → 印を墓地詠唱 → ガジラビュート蘇生(シールド1枚焼却) → #2が2枚ブレイク
ガジラビュート(SA)がダイレクトアタック → 1ターンで勝利
```

**歴史上のMRCワンショットが、精密スクリプトのみで初めてシミュレーター内に再現された。**
ループ探索器の「陰性」(サガ型は現プールに不在)に続き、「陽性」方向の能力
(実在エンジンを正しく回せる)も実証されたことになる。回帰テスト化済み
(tests/test_loop_finder.py::MRCEngineReproductionTest)。

実装中に発見・修正したデータ起因バグ: 多色表記が「闇火」(区切りなし)のカードがあり、
文明フィルタの完全一致が失敗していた→部分一致に修正。

次: loop-find の静的スクリーニングに「呪文再装填型」(on_attack cast_from_grave ↔
蘇生呪文の往復)の検出を追加すれば、MRC族の網羅列挙が可能になる。


## 第四弾: 呪文再装填型の自動検出(2026-06)

loop-find の静的スクリーニングに「呪文再装填型」を追加した:
攻撃時詠唱エンジンE(on_attack cast_from_grave)と、Eを蘇生できる呪文S
(on_cast summon_from_grave)の往復成立を機械判定し、SのSA付与有無で
「ワンショット候補/持続型」に分類。動的検証はエンジン1体+墓地(S4・E3)から
攻撃フェイズを実走し、詠唱・蘇生回数と1ターンキル成立を計測する。

**exact限定での実行結果**:

```
[ワンショット候補] 暗黒GUY・ゼロ・ロマノフ + 煉獄と魔弾の印
  → ★1ターンキル(詠唱4回・シールド5枚)を自動検出
[持続型] ゼロ・ロマノフ + インフェルノ・サイン → 蘇生1回(SA無しのため跨ターン型)
```

人手で再現した前章のMRCワンショットを、**探索器が静的列挙→動的証明まで全自動で
到達できる**ことを確認した。exactキュレーションを増やすほど、この網に
未知のエンジン対が掛かる体制が完成した。

ループ探索器の対応族: サガ型(相互/自己蘇生)・ヒドラ型(回収)・呪文再装填型(MRC族)。
未対応: フシギバース型(置換効果)・超次元型。


## 第五弾: 網の拡大と【ロマノフサイン】の自律的再発見(2026-06)

プール全体から「攻撃時詠唱」を持つカードと無条件蘇生呪文を機械抽出し、
無条件のもの4種(邪眼皇ロマノフI世/狂気と凶器の墓場/戒王の封/魔法特区 クジルマギカ)を
exactキュレーションに追加した(計21種)。再走結果:

```
[ワンショット] 暗黒GUY・ゼロ・ロマノフ + 煉獄と魔弾の印 → ★1ターンキル(既知)
[ワンショット] 邪眼皇ロマノフI世 + 煉獄と魔弾の印 → ★1ターンキル(新検出)
[持続型] ラスト・ロマノフ × 戒王の封 / ゼロ・ロマノフ × 戒王の封・サイン(新検出)
```

**「ロマノフI世+印」は組み合わせを人間が指定したものではなく、個々のカードを
原文どおりexact化しただけで探索器が自力で対にし、1ターンキルを証明した。**
この対は本家で実在した名デッキ【ロマノフサイン】の核そのものであり、
コンボ発掘(デ・スザーク骨格)・役割探索(ボルコン/連ドラ)に続き、
**ループ探索の階層でも歴史的収束が起きた**。

体制の現状: exactキュレーション1枚追加ごとに、既存の全exactカードとの
エンジン対が自動照合される。「人間がまだ気づいていない対」が掛かる条件は
(1) 部品が現プールに存在し、(2) 無条件(または将来、条件モデル化済み)であること。


## 第六弾: 【黒単ロマノフサイン・再誕】のデッキ化とメタ判定(2026-06)

自律発見したエンジン対を核に、全40枚がexactスクリプト済みの黒単デッキを構築した
(generated_decks id=20、カタログ掲載済み)。エンジン: ロマノフI世4+印4を軸に、
肥やし(ヴォジャワ/墓場/ラスト・ロマノフ)、蘇生(サイン/戒王の封)、
焼却(ガジラビュート)、ルーター(ソー☆ギョッ)。

**メタ判定: 絶対強さ43.6**(対スコーラー68%・対火光58%だが、自己対戦アグロ群に17〜29%)。
エンジンは組めれば1ターンキル(証明済み)だが、組み上がりの数ターンを速攻に
咎められる——**史実のロマノフサインが持っていた強みと弱みの両方が再現された**。
試合時間も平均15〜21ターンとコンボらしい長さ。

改善余地: 方策がエンジン組立(ロマノフ着地→攻撃)を優先しない、
ソー☆ギョッの捨て札がランダム(本来はロマノフ/印を選んで捨てたい)。
コンボ方策のMRC型対応(エンジン優先の行動規則)が次の伸びしろ。


## 第七弾: コンボ方策のMRC型対応——アブレーションが暴いた「保護しすぎ」の罠(2026-06)

前章の改善余地「捨て札の選択・エンジンのチャージ保護」を方策に実装した。
Policy基底に `choose_discard` フックを追加し、実行器の `discard_own_hand` が
コントローラーの方策に捨て札を問い合わせる(Noneならランダムにフォールバック)。
ComboPolicyは `bind()` で効果マップからエンジン(on_attack cast_from_grave)と
蘇生呪文(on_cast summon_from_grave)を抽出し、墓地適性カードを選んで捨てる。

**第一版は大失敗だった。** 墓地適性カード全体(エンジン+蘇生呪文=デッキの半分)を
マナチャージから保護したところ、id=20の強さは43.0→**29.4**へ暴落。
要因分解(各100試合×8相手、同一シード):

| 方策 | 強さ |
|------|------|
| Greedy(基準) | 43.0 |
| Combo(G・ゼロのみ) | 43.0 |
| 選択捨てのみ | 41.2 |
| チャージ保護のみ(全墓地適性) | **28.4** |
| 保護をエンジン限定+全保護時は貪欲退避 | **45.8** |

主犯はチャージ保護の**選択効果**: 保護されないカードから順にマナへ消え、
手札は保護カードだけになり、以後チャージ不能→マナが4〜5で永久に止まり
蘇生呪文(コスト5〜7)を唱えられない。「墓地に置きたい」と「マナが要る」は
同じ資源を奪い合うため、保護は希少部品(エンジン本体6枚)に絞り、
手札が保護対象のみになったら貪欲に退避するのが正解だった。

**最終形: 43.0→45.8(+2.8)**。内訳は自己対戦アグロ群への耐性改善が大きい
(R1: 20→28% / R2: 37→48% / R3: 19→26%、デンジャデオン57→64%)。
エンジンが手札に温存され、サインからの蘇生が安定したことで
中速相手の捲り合いに強くなった。実装はテスト153件で固定済み
(選択捨て・エンジン保護・全保護時退避・実行器の方策問い合わせ)。

教訓: **コンボ方策の規則は1つずつ計測して入れる。**「良さそうな規則」の
複合は、要因分解しなければ29.4のまま「MRC対応は逆効果」と誤結論していた。
測定スクリプトは scripts/measure_combo_mrc.py に保存。


## 第八弾: エンジン組立規則と「方策込みレーティング」(2026-06)

第七弾の教訓(規則は1つずつ計測)に従い、エンジン組立の行動規則2つを
個別にアブレーションした(id=20、各100試合×8相手、同一シード、基準45.8):

| 規則 | 強さ | 採否 |
|------|------|------|
| 蘇生呪文優先(墓地にエンジンがあれば召喚より先に唱える) | **47.5** | 採用 |
| エンジン先制攻撃(攻撃時詠唱の連鎖を狙って先に殴る) | **40.8** | 不採用 |
| 両方 | 42.1 | — |

蘇生呪文優先が効くのは、貪欲方策が「クリーチャー優先」のため蘇生呪文を
後回しにし、エンジンが墓地に眠ったままになっていたから。一方の先制攻撃は、
貪欲の「勝てるクリーチャー戦を先に取る」判断を上書きしてしまい、
有利交換を捨ててブロッカーや除去に突っ込むぶん大きく損をした。
直感的に「コンボ的に正しい」規則でも、計測なしでは採用できない好例が続いた。

**累計: Greedy 43.0 → MRC対応コンボ方策 47.5(+4.5)**。

あわせて `rate_deck_against_meta` に `policy_factory` 引数を追加し、
CLIの `--policy` が rate / rate-generated にも効くようにした:

```bash
python -m src.battle.research --policy combo rate-generated --id 20
```

これまでの絶対強さスコアは全てGreedy操作の値であり、コンボデッキは
**操作方策の分だけ過小評価されていた**(本デッキで4.5pt)。今後コンボ系の
生成デッキを評価するときは `--policy combo` の値を併記すること。
相手側は比較可能性のため常にGreedyで固定している。


## 第九弾: MRC核をロックした進化探索——「コンボは荷物になった」(2026-06)

MRC対応方策が世代選別(両側コンボ方策)と最終判定(--policy combo)の両方に
入った初の条件で、id=20をシードに進化探索を実行した:

```bash
python -m src.battle.research --games 100 --seed 31 --policy combo \
  hybrid-search --generations 12 --population 14 \
  --civilizations 闇,火,水,無色 --seed-deck-id 20 \
  --lock "邪眼皇ロマノフI世,煉獄と魔弾の印"
```

結果は **絶対強さ61.3**(id=21【黒赤ロマノフ・ブリッツ】、別シード再測定で65.1)。
手組みのid=20(コンボ方策47.5)を大きく超えた——が、中身を検証すると
進化は予想と違うことをしていた。

**進化は墓地肥やしを全廃した。** ヴォジャワ/狂気と凶器の墓場/サイン/ソー☆ギョッは
1枚も残らず、シェルは2〜3コストの黒赤アグロ(ザビフライ/ダチッコ・チュリス/
ブッチビーズ等)に置き換わった。効果ログを数えると、ロックした
エンジンの発火は**3〜6/50試合**(ロマノフは57回詠唱を試みるが墓地に呪文がない)。
61.3の出どころはテンポであり、ロマノフ4+印4はほぼ「8枚の荷物」だった。

蘇生呪文の発動条件を一般化した方策(墓地に蘇生対象がいれば印を唱える)も
試したが、発火は2倍(6/50)になるものの強さは65.1→65.5で誤差内。不採用とし、
試作は scripts/measure_combo_mrc.py の ComboReviveValue に残した。

**知見: 選別圧はコンボを強化しない。コンボを荷物にしたまま勝てるシェルを選ぶ。**
MRCエンジンは「肥やしに数ターン投資して初めて回る」構造のため、
その投資はこのメタ(速攻が上位)ではテンポ負けとして即座に罰される。
史実でMRCが専用構築(全カードを墓地戦略に捧げる)だったことと整合する:
**コンボデッキは部分採用が利かず、全振りか不採用かの二択**になる。
未開拓コンボを探索で発掘するには、ロックだけでは足りず、
「エンジン発火率」を選別関数に組み込む必要がある(chain成立率と同じ構図)。


## 第十弾: 発火圧付き進化——進化がエンジン一式を自力で再構築した(2026-06)

第九弾の対策として、選別関数に「エンジン発火率(墓地詠唱・蘇生が成立した
試合の割合)」を組み込んだ(`hybrid-search --engine-weight`)。カーネルが
効果成立をログと無関係に常時カウントするため、選別コストは増えない。

第九弾と完全同条件(id=20シード、ロマノフI世+印ロック、12世代、同シード)に
`--engine-weight 0.25` だけを加えた対照実験の結果(強さ/発火率は
コンボ方策・各100試合×8相手・同一シードで再測定):

| デッキ | 強さ | 発火率 | 備考 |
|--------|------|--------|------|
| id=20 黒単ロマノフサイン・再誕(手組み) | 47.5 | 61.9% | 全カードexact |
| id=21 黒赤ロマノフ・ブリッツ(発火圧なし) | 65.1 | 2.4% | コンボは荷物 |
| id=22 邪眼転生ロマノフサイン(発火圧0.25) | **59.1** | **75.5%** | **両立** |

id=22は手組みのid=20を**強さ(+11.6)と発火率(+13.6pp)の両軸で上回った**。
進化の中身が雄弁で、発火圧は墓地肥やし一式(ソー☆ギョッ4/ヴォジャワ4/
墓場4/サイン4/印4/戒王3)を**淘汰から守るどころか自力で復元**し、
フィニッシャー枠をガジラビュート2+バルクライ王2+XENOM2+デ・スザーク2へ
組み替えた。バルクライ王は史実のロマノフ系デッキの実在の相棒だが、
シミュ上はバニラ扱い(進化条件が未対応)なので「正しいカードを別の理由
(打点)で選んだ」点は割り引いて読むこと。

発火元の内訳(120試合): ロマノフ223回/墓場87/サイン73/印62/戒王41が
exactスクリプト由来で全体の97.4%。approxスクリプトを持つデ・スザークの
寄与は13回(2.6%)に留まり、発火率は捏造ではない。

**結論: コンボデッキの探索は「ロック+発火圧」で初めて閉じる。**
ロックは骨格を守るが進化はそれを荷物にする(第九弾)。発火率を適応度に
入れると、進化は「勝ちながら回る」均衡点を自分で見つける。強さの代償は
6pt(65.1→59.1)であり、これが現メタにおける「コンボを回すことの価格」の
定量値になった。次の応用: combo-mine の --evolve にも engine_weight を
渡せば、未知のエンジン対の発掘→デッキ化まで全自動で同じ品質が出るはず。


## 第十一弾: 全自動パイプラインと三つの捏造事件——進化は最強のファザーである(2026-06)

combo-mine --evolve に発火圧を接続し「発掘→動的証明→発火圧付きデッキ化」を
全自動化した。その実走が、シミュレータの誤読を立て続けに暴いた。

**事件1: 父なる大地(id=23, 偽の強さ77.0)。** 原文「相手のマナゾーンから選び、
相手はこれをバトルゾーンに出す」(妨害)を、approxスクリプトがscope欠落で
「自分のマナから踏み倒す」と誤読。進化はコスト51のギュウジン丸をマナに
チャージ→誤読の父なる大地で4ターン目に着地、という捏造コンボを最適化した。
→ summon_from_manaにscope/exclude_evolution実装、父なる大地をexact化、
combo-mineの提案をexact限定にゲート(loop-findと同じ忠実度ゲート)。

**事件2(修正中に発覚): 幻の0%と死にコード。** exact限定にすると全チェーンが
成立率0%に。原因は2つ: (a)打点持ちツインパクトはクリーチャーとしてプレイ
されるため呪文面のon_castはカーネルで発火しない死にコード(デーケン/ルソーを
環とする提案は全て幻)、(b)goldfishのチャージ規則「出せない最高コスト」が
チェーンの環(中〜高コスト)を系統的にマナへ沈めていた。
→ 提案の環は「実際に発火するトリガー」のみから抽出、検証器はチェーン部品を
チャージから保護(パイロットの意図の再現)。修正後は35〜38%の妥当な成立率。

**事件3: ストーム・クロウラー(id=24, 偽の強さ72.5)。** 再走の成果の発火率
85.6%を検証すると、発火の90%が「マナから1枚を手札に戻す」を
summon_from_manaと誤読したapproxスクリプト由来だった。下書き生成器の
「バトルゾーンに出」が「出た時」のトリガー句に誤反応していたのが根因。
→ regexを他動詞「出す/出し」に限定し、自動承認1,626件をdraft降格→全再生成→
再承認。さらに**発火指標の発生源をexactスクリプトに限定**(fire_source_ids)し、
approxが指標を荒稼ぎする構造自体を遮断した。

**正本の成果: id=25【黒単戒王リアニメイト】強さ52.8(標準条件55.0)、
chain成立率36.7%、exact発火率15.2%、発火源は戒王の封のみ=捏造ゼロ。**
ヴォジャワ肥やし→戒王の封→アマデウス/ヴィオラ・ソナタという、実ルールで
本当に回るリアニメイトデッキを全自動で発掘・構築できた。なお誠実な指標では
進化後(52.8)がシード(61.1)を下回ったため、良い方を保存する保険を追加した。

**教訓: 進化探索はシミュレータ忠実度に対する最強のファジングツールである。**
誤読スクリプトが1枚でもあれば、進化は必ずそれを見つけて「一番強い嘘」を
組み上げる(77.0→72.5はどちらも当時の全デッキ中最強級だった)。
高スコアが出たときほど発火源の内訳検証(approx混入チェック)が必須。
指標に使う信号(発火率・chain・ループ署名)は全てexact由来でなければならない。

残課題: ツインパクトの両面プレイ(カーネル機能)、approved approxの
原文照合監査(誤読健診)、コンボ進化がシードを安定して超えるための
多目的バランス調整。


## 第十二弾: トリガー句剥がしの誤読健診——首位が逆転した(2026-06)

三事件の根本原因「トリガー句を含む文全体への素朴なキーワードマッチ」を
構造的に塞いだ。効果抽出の前に文頭のトリガー句(「〜時、」)を取り除く
前処理を生成器に追加し(条件句「〜なら」は意味が変わるため対象外)、
自動承認1,608件を全再生成して差分を健診した。

**結果: 27件のスクリプトが修正された。** 代表例:
- 飛行男/ザビフライ/エミリー: 「破壊された時、相手の手札を捨てさせる」の
  トリガー句「破壊された」が効果側の「相手」と誤結合し、**死ぬたびに相手
  クリーチャー1体を道連れにする捏造除去**が付いていた
- 剛撃妖精ユキハナ: 「捨てられた時」句から捏造ハンデスが生えていた

修正後の統一条件で主要デッキを再測定すると、**順位が逆転した**:

| デッキ | 修正前 | 修正後 | exact発火率 |
|--------|--------|--------|------|
| id=21 黒赤ブリッツ(アグロ+荷物) | 65.1 | **57.9** | 2.5% |
| id=22 邪眼転生ロマノフサイン | 59.1 | **60.1** | 76.4% |
| id=25 黒単戒王リアニメイト | 55.0 | 55.2 | 15.5% |
| id=20 手組みロマノフサイン | 47.5 | 49.6 | 62.7% |

id=21はザビフライ4枚の捏造除去で7.2pt水増しされていた。誠実な物理では
**「勝ちながら回る」id=22が全ロマノフ系の首位**であり、第十弾の
「コンボを回す価格6pt」はほぼ消滅(60.1 vs 57.9で逆にコンボ側が上)。
発火圧付き進化の成果は、シミュレータが正確になるほど価値が上がる。

教訓: 誤読健診は探索の前提インフラである。スクリプトの誤りは特定デッキを
歪めるだけでなく、**デッキ間の比較・進化の選別・研究上の結論(コンボの価格)
まで連鎖的に歪める**。スナップショット→全再生成→差分監査→主要デッキ
再測定、を生成器を触るたびの標準手順とする。
