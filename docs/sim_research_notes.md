# 厳密シミュレーション研究ノート

シミュレーション基盤の現状・既知の近似・再現手順を記録する。
(ロードマップ本体は `docs/roadmap_v2_simulation.md`)

## 再現手順

```bash
# 1. EffectScript整備(下書き生成 → 再生成 → 完全変換ぶん一括承認 → キュレーション適用)
python -m src.battle.research prepare-effects

# 2. メタ総当たり戦
python -m src.battle.research --games 100 --seed 5 meta-tournament
```

## EffectScript整備の3層構造

1. **自動下書き** (`draft_generator.py`): 正規表現でテキストから命令を抽出。
   注釈括弧・カーネルキーワード行・構造トークン(【LINE】等)を変換済み扱いにする。
2. **一括承認** (`approve_clean_drafts`): テキストを完全変換できた下書きのみ自動承認。
   部分変換はdraftのまま残しレビュー対象とする。
3. **キュレーション** (`data/effect_scripts/curated_meta.json`): 自動変換できない複雑カードへの
   人手/AIによる近似定義。カード名キーで、`prepare-effects` のたびに承認済みとして上書き適用される。
   **複雑カードの効果を追加するときはこのファイルに追記するのが最短経路。**

現状: 全5178カード中、承認済み1108(21.4%)。収集済みメタデッキ5種のカードは
ほぼ100%承認済み(自然単のみ18/20)。

## メタ総当たり結果の変化(games=100, seed=5)

| デッキ | 効果なし | キュレーション後 |
|---|---|---|
| 火水レイド | 80.2% | 83.5% |
| 火光レイド | 81.8% | 61.7% |
| 自然単デンジャデオン | 8.8% | 45.0% |
| 光単裁きの紋章Z | 14.0% | 40.0% |
| 水単スコーラー | 38.0% | 17.8% |

効果未実行だった頃は「呪文が不発の遅いデッキ」が一方的に負け、試合の過半が
ターン上限引き分けになる対面もあった。キュレーション後は受け札・除去・全体タップが
機能し、デッキタイプ間の相性構造が出るようになった。

## 既知の近似・制約(評価時に留意)

- **未対応メカニズム**: サバキZ、B・A・D、G・ゼロ、超次元、追加ターン、特殊勝利、
  コスト軽減/増加、置換効果、パワー修正、「選ばれない」。該当カードはキュレーションで
  縮小近似 or バニラ扱い(curated_meta.json の note に明記)。
- **水単スコーラー(17.8%)は実態より弱い**: 勝ち筋(G・ゼロ+追加ターン)が丸ごと未対応のため。
  このデッキの評価は現状信頼できない。
- **選択・条件付き効果**: 「次のうちいずれか」「そうした場合」は固定モードで近似。
- **対象選択ヒューリスティック**: 効果の対象は最大パワー優先。方策による選択はv2.0残課題。
- **ツインパクト**: パワーを持てばクリーチャー面で運用(呪文面は片面のみ反映)。
  コスト0登録のツインパクトがDBに存在し、無償プレイになるデータ品質問題あり。
- **方策**: 既定は貪欲。`LookaheadPolicy`(攻撃の1手読み+determinization)は
  現メタミラーで貪欲と同等(51%)。ブロッカー・受け効果が増えるほど有利になる見込み。

## 次に効くこと(優先順)

1. 水単スコーラーの勝ち筋(呪文カウント+追加ターン)のモデル化、または評価対象からの除外フラグ
2. 効果対象選択のPolicy化(現状は最大パワー固定)
3. コスト軽減の近似(例: 条件を無視した固定軽減)
4. ツインパクトのコスト0データ修正(取り込み側)
5. 生成デッキ(generated_decks)を research CLI から直接レーティングする入口
