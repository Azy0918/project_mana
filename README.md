# Project MANA

デュエル・マスターズ プレイス向けのカードDB検索ツールです。
MVPとして、カードCSVの取り込み、カード検索、タグベースのデッキ生成、簡易デッキ評価を実装しています。
完全な強さ判定や厳密な対戦シミュレーションはまだ含めていません。
これらの実現に向けた次バージョン計画は `docs/roadmap_v2_simulation.md` を参照してください。

## v1.0.0 概要

Project MANA v1.0.0 は、カードDB整備、デッキ生成、評価、実戦ログ、改良履歴、検証計画、研究レポートまでを一通り扱える研究用MVPです。

Windowsでは、初回は `setup_app.bat`、通常起動は `run_app.bat` を実行します。
Pythonやpipのコマンドを直接覚えなくても起動できる構成にしています。

## セットアップ

### Windows初回セットアップ

Windowsでは、まず以下を実行します。

```bat
setup_app.bat
```

このバッチは以下を自動で行います。

- Python存在チェック
- `.venv` の作成
- `pip install -r requirements.txt`
- `data/cards.db` の初期化

Pythonが見つからない場合は、Python 3.12以上のインストール案内を表示します。

### 手動セットアップ

Windows以外、または手動でセットアップする場合は以下です。

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
python src/import_cards.py
```

環境によっては `python` の代わりに `py -3`、macOS/Linuxでは `.venv/bin/python` を使ってください。

既にPython環境を用意している場合は、最低限以下でも動かせます。

```bash
pip install -r requirements.txt
```

AIデッキ生成を使う場合は、プロジェクト直下に `.env` を作り、APIキーを設定します。

```env
OPENAI_API_KEY=your_api_key_here
```

使用モデルは必要に応じて変更できます。

```env
OPENAI_MODEL=gpt-5-mini
```

## カードDBの作成

```bash
python src/import_cards.py
```

取り込み後、`data/cards.db` が作成されます。

アプリ起動時にも `data/cards.csv` から `data/cards.db` への自動反映を行います。
DBが未作成、`cards` テーブル件数がCSVより少ない、または `card_tags` テーブルがない場合は、既存の取り込み処理で `cards` / `card_tags` を作り直します。
Streamlit Cloud では、リポジトリ内の `data/cards.csv` を元に起動時DBが復元されます。

## トラブルシューティング

### `python` が見つからない

Python 3.12以上をインストールしてください。
Windowsではインストール時に `Add python.exe to PATH` にチェックを入れてください。
インストール後、ターミナルを開き直して `setup_app.bat` を再実行します。

### `pip` が使えない

まず `setup_app.bat` を使ってください。
それでも失敗する場合は、Pythonを再インストールし、pipを含めた標準構成でインストールしてください。

### Pythonの対話モードに入ってしまう

`python` だけを実行すると対話モードになります。
Windowsでは `run_app.bat` を実行してください。
手動起動の場合は `streamlit run app.py` を実行します。

### Streamlitが起動しない

依存ライブラリが入っていない可能性があります。
`setup_app.bat` を再実行してください。
手動の場合は `pip install -r requirements.txt` を実行します。

### AIデッキ生成でAPIキーエラーになる

`.env.example` を参考に、プロジェクト直下へ `.env` を作成してください。

```env
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=gpt-5-mini
```

APIキー本体はGit管理に含めないでください。

### DBを作り直したい

`data/cards.csv` を確認してから、以下を実行します。

```bash
python src/import_cards.py
```

Windowsでは `setup_app.bat` を再実行してもDB初期化できます。

## デッキ生成

`デッキ生成` 画面で条件を入力し、`条件からデッキを生成` を押します。
入力できる条件は以下です。

- デッキ名
- 使用文明
- 想定デッキタイプ
- 重視タグ
- 避けたいタグ
- 想定・戦略メモ
- デッキ枚数
- 初動・マナ加速、受け札、フィニッシャーの比率

生成ロジックは `card_tags` と入力条件を参照し、カードごとにスコアを付けます。
文明一致、重視タグ一致、デッキタイプ一致を加点し、避けたいタグを含むカードは減点します。
そのうえで、以下の役割比率を優先してデッキを組みます。

- 初動 / マナ加速
- 受け札
- フィニッシャー

同名カードは最大4枚までです。
カードプールが少ない場合は、条件を満たせる範囲で40枚に近づけます。
生成結果には、使用した生成条件と条件への適合度も表示します。

適合度では以下を確認できます。

- 文明一致率
- 重視タグ一致数
- 避けたいタグ混入数
- 初動枚数
- 受け札枚数
- フィニッシャー枚数
- 除去枚数
- ドロー/リソース枚数
- 平均コスト
- 条件適合スコア
- 不足カテゴリ警告
- 改善コメント

## 一人回しシミュレーション

`一人回しシミュレーション` 画面では、生成デッキまたは入力デッキを使って簡易的な一人回しを実行できます。

MVPの前提は以下です。

- デッキをシャッフル
- 初手5枚
- 毎ターン1枚ドロー
- 毎ターン1枚マナチャージ
- デフォルトは5ターンまで
- デフォルトは1000回試行
- 判定は `card_tags` ベース

計測項目は以下です。

- 初動成功率
- マナ加速確認率
- 受け札確認率
- フィニッシャー確認率
- 初動ターン分布

初動成功率は、指定ターンまでに `初動` または `マナ加速` タグを持つカードを使える見込みになった割合です。
確認率は、指定ターンまでに該当タグのカードを手札またはドローで確認できた割合です。

## 簡易AI対戦

`簡易AI対戦` 画面では、デッキAとデッキBを入力してタグベースの簡易対戦を実行できます。
生成済みデッキをデッキAまたはデッキBとして使うこともできます。

MVPの前提は以下です。

- 完全なルール再現ではなく、研究用の傾向推定
- 100〜1000回試行
- 試行ごとにランダム性を追加
- 勝率と平均決着ターンを算出
- 有利要因、不利要因を日本語で表示

簡易評価に使う要素は以下です。

- 初動速度
- マナ加速
- 受け札
- フィニッシャー
- ドロー / リソース
- 除去
- メタカード
- マナカーブ
- 総合スコア
- 未知性スコア
- メタ適性スコア

## 進化探索

`進化探索` 画面では、遺伝的アルゴリズム風の探索で多数のデッキ候補を評価します。
完全な最適化ではなく、研究用に「良さそうな候補」を探すMVPです。

探索の流れは以下です。

- 初期デッキ群を複数生成
- 各デッキを `evaluate_deck()` で評価
- 総合スコア、未知性スコア、メタ適性スコアから適応度を計算
- 上位デッキをエリートとして残す
- 突然変異でカード差し替え、枚数変更を行う
- 複数世代を実行
- 世代ごとの最良デッキを記録

指定できる項目は以下です。

- 世代数
- 個体数
- 文明
- 重視項目
- 乱数シード

重視項目は以下です。

- バランス
- 強さ重視
- 未知性重視
- メタ適性重視

結果として以下を表示します。

- 総合最良デッキ
- 未知性最大デッキ
- メタ適性最大デッキ
- 世代ごとのスコア推移

カードプールが少ない場合でも落ちないよう、可能な範囲で40枚と同名4枚制限を保ちながら探索します。

`研究ログ` 画面では、保存した研究データを一覧・集計できます。

追加テーブルは以下です。

- `evaluation_logs`
- `battle_logs`
- `evolution_logs`

保存できる内容は以下です。

- デッキ評価結果
- 生成デッキの評価結果
- 簡易AI対戦結果
- 進化探索の世代ログ

表示できる統計は以下です。

- 保存済み評価の一覧
- 平均スコア
- 最高スコアデッキ
- 未知性最大デッキ
- メタ適性最大デッキ
- 世代ごとのスコア推移

評価ログ、対戦ログ、進化探索ログはCSVとしてダウンロードできます。

## 対戦ログ

`対戦ログ` 画面では、実戦の対戦記録をSQLiteに保存できます。

保存できる項目は以下です。

- 使用デッキ名
- デッキリスト
- 相手デッキタイプ
- 先攻 / 後攻
- 勝ち / 負け
- 決着ターン
- 勝因
- 敗因
- 使用カード・活躍カード
- 腐ったカード
- プレミ・分岐判断メモ
- 動画ファイルパス / URL
- メモ

保存先テーブルは `real_match_logs` です。
保存済みログから以下を集計できます。

- デッキ別勝率
- 相手デッキタイプ別勝率

対戦ログはCSVとしてダウンロードできます。

### 実戦成績フィードバック

`対戦ログ` 画面では、実戦ログと保存済みデッキ評価を突き合わせてフィードバックを表示します。

確認できる項目は以下です。

- デッキ別の実戦勝率
- AI評価スコアと実勝率の比較
- 仮想メタ適性スコアと実勝率の比較
- 相手デッキタイプ別の弱点分析
- 活躍カードランキング
- 腐ったカードランキング
- 先攻/後攻別勝率
- 平均決着ターン
- 改善候補コメント

実戦ログの `deck_name` と、保存済み評価ログのデッキ名が一致している場合、AI総合スコアやメタ適性スコアとの差分も表示します。

### デッキ改良候補

`対戦ログ` 画面では、実戦成績フィードバックをもとに改良デッキ案のたたき台も生成できます。

MVPの改良ロジックはAIを使わず、ルールベースで以下を行います。

- 苦手対面から必要タグを推定
- 先攻/後攻勝率差から必要タグを推定
- 腐ったカードを削減候補として表示
- 現在の文明に近いカードから差し替え候補を検索
- 改良デッキ案を生成
- 改良前後の総合スコア、未知性スコア、メタ適性を比較

弱点タグの例は以下です。

- 速攻に弱い: `受け札` / `S・トリガー` / `除去` / `初動`
- コントロールに弱い: `ドロー` / `リソース` / `フィニッシャー` / `ハンデス`
- コンボに弱い: `メタカード` / `ハンデス` / `速攻`
- 後攻勝率が低い: `初動` / `受け札` / `S・トリガー`

生成した改良案は、デッキ評価画面へ送って再評価できます。
また、改良案はデッキバージョンとして保存できます。

## デッキ履歴

`デッキ履歴` 画面では、改良デッキ案をバージョンとして保存し、成長履歴を確認できます。

追加テーブルは以下です。

- `deck_versions`
- `deck_changes`
- `test_plans`
- `test_plan_targets`

保存できる内容は以下です。

- デッキ名
- バージョン名
- 親バージョンID
- デッキリスト
- 改良理由
- 総合スコア
- 未知性スコア
- メタ適性スコア
- メモ
- 追加カード / 削減カード

確認できる項目は以下です。

- デッキごとのバージョン一覧
- 親デッキ・子デッキの系譜
- 差し替えカード履歴
- バージョン別の実戦勝率
- 親子間の勝率差、総合スコア差、未知性差、メタ適性差
- デッキバージョンCSVエクスポート
- 差し替え履歴CSVエクスポート
- テスト計画CSVエクスポート
- 重点対面CSVエクスポート

実戦勝率は、実戦ログの `使用デッキ名` がデッキ名またはバージョン名と一致するログから集計します。
改良版ごとに実戦ログを残す場合は、`使用デッキ名` にバージョン名を入れると比較しやすくなります。

### 検証計画

`デッキ履歴` 画面では、各デッキバージョンに対して実戦テスト計画を作成できます。

設定できる項目は以下です。

- 検証目的
- 目標試合数
- 目標勝率
- 目標平均決着ターン
- 重点対面
- 重点対面ごとの目標試合数
- 重点対面ごとの目標勝率
- 検証メモ

保存した計画は、実戦ログと自動で突き合わせて進捗を表示します。
実戦ログの `使用デッキ名` が、計画に紐づくデッキ名またはバージョン名と一致するログを集計対象にします。

表示される判定は以下です。

- `検証完了`: 目標試合数、勝率、平均決着ターン、重点対面条件を満たしている
- `継続`: まだ試行数が不足している
- `再改良`: 試行数は足りているが成功条件に届いていない

重点対面ごとに、あと何戦必要か、目標勝率に届いているかも確認できます。

## CSV管理

`CSV管理` 画面では、`data/cards.csv` を手入力で増やすための品質チェックとタグ候補表示を行います。
公式カード情報の自動取得はまだ行わず、手入力CSVの品質を上げるためのMVPです。

バリデーション項目は以下です。

- 必須列チェック
- `card_id` 重複チェック
- `name` 空欄チェック
- `cost` 数値チェック
- `tags` 空欄チェック
- `civilization` の表記ゆれチェック
- エラー/警告一覧の表示

タグ候補ルールは以下です。

- `S・トリガー` -> `S・トリガー` / `受け札`
- `マナゾーン` -> `マナ加速`
- `カードを引く` -> `ドロー`
- `破壊` -> `除去`
- `スピードアタッカー` -> `速攻`
- `ブロッカー` -> `ブロッカー` / `受け札`
- `進化` -> `進化`
- `手札を捨てる` -> `ハンデス`
- `山札から` -> `サーチ候補`

行ごとのタグ候補と、自由入力テキストからのタグ候補を確認できます。

### カード登録・編集

`CSV管理` 画面では、`cards.csv` にカードを1枚ずつ追加できます。

追加時には以下を行います。

- タグ候補の選択追加

- `cards.csv` への安全な追記
- 保存後のCSV検査結果表示

既存カードの検索・編集にも対応しています。
カード名または能力テキストで検索し、対象カードを選んで更新できます。

編集時にも以下を行います。

- 文明のプルダウン選択
- カードタイプのプルダウン選択
- 能力テキストからタグ候補を表示
- タグ候補の選択追加
- 保存前バリデーション
- 保存前の自動バックアップ作成
- 既存カードの更新
- 保存後のCSV検査結果表示

CSVを直接編集しなくてもカードDBを増やせるため、入力ミスを減らしながらデータ整備を進められます。

## AIデッキ生成

`AIデッキ生成` 画面では、OpenAI APIを使ってデッキ案を生成できます。
APIキーは `.env` の `OPENAI_API_KEY` から読み込み、コードには直書きしません。

入力項目は以下です。

- フォーマット
- 文明
- コンセプト
- 必ず使いたいカード
- 対策したい相手

アプリはカードDBから候補カードを抽出し、AIには候補カードだけを渡します。
AIには、候補カードだけを使って40枚デッキを作るよう指示しています。

出力項目は以下です。

- デッキ名
- 40枚リスト
- 基本戦略
- 採用理由
- 弱点
- 改造候補
- 未知性スコア
- 実戦テスト項目

既存テンプレートの再現よりも、未知アーキタイプ候補として検証価値のある案を出す方針です。
AI出力の40枚リストを `デッキ評価` 画面に貼り付けると、未知性スコアを含めて評価できます。

## CSV形式

```csv
card_id,name,civilization,cost,card_type,power,race,text,tags
```

```csv
DMPC-006,フェアリー・ライフ,自然,2,呪文,,,"S・トリガー。自分の山札の上から1枚目をマナゾーンに置く。",S・トリガー;マナ加速;初動
```
